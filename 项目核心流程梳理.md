## 1. 项目定位与整体架构

**EvoMAS = Evolutionary Synthesis of Multi-Agent Systems**：用大模型元算子（Selection / Generate / Mutate / Crossover / Update-Memory）在"多智能体配置空间"（MAS Pool）里**搜索最优团队配置**，再把找到的配置在目标 benchmark（SWE-bench Verified / BBEH / WorkBench 三大套件）上跑测试得到 reward。

### 1.1 两种运行模式

项目同时支持 **Baseline 模式**（不演进，拿 Pool 里某一个固定配置跑全量 case，用于建立参考基线）和 **Evolution 模式**（Meta-Model 迭代生成/交叉/变异 MAS 配置，按 reward 反馈筛选优解，用于探索更优团队形态）。

```
                       ┌─────────────────────────────────────────────┐
                       │            Meta-Model (Claude Sonnet 4.5)   │
                       │   Selection → Generate/Mutate/Crossover →   │
                       │    Compute Reward → Pool Update → Memory    │
                       └────────────────────┬────────────────────────┘
                                            │ 产出 MAS Config (YAML)
                                            ▼
                  ┌──────────────────────────────────────────────────┐
                  │            interpret_mas() / MasRunner           │
                  │   读 Pool YAML  →  构造 Agent Team → 跑 case     │
                  │   → 输出 patch / 答案 / run.log / results.json  │
                  └─────────────────────┬────────────────────────────┘
                                        │
                       ┌────────────────┴─────────────────┐
                       ▼                                  ▼
            ┌──────────────────────┐          ┌──────────────────────────┐
            │ 生成阶段产物         │          │ 评估阶段                 │
            │ · <task_id>.txt      │          │ · LLM-as-judge            │
            │ · run.log            │          │ · local_swe_evaluator     │
            │ · results.json       │          │ · swebench.run_evaluation │
            │ · duration/tokens    │          │   (Docker Harness 推荐)   │
            └──────────────────────┘          └──────────────────────────┘
```

## 2. 核心调用链（ChatDev Baseline + Docker，当前默认路径）

### 2.1 用户命令（4 域并行 bash 脚本）

```bash
bash scripts/run_chatdev_baseline.sh
```

[run_chatdev_baseline.sh](file:///home/xhgong/project/EvoMAS/scripts/run_chatdev_baseline.sh) 实质是把下面这条命令对 `django / sympy / matplotlib / scikit-learn` 四个域分别起后台进程：

```bash
python main.py \
    --dataset swe_bench_verified \
    --baseline chatdev \
    --task-ids-file scripts/selected_<域>.txt \
    --llm-as-judge none \
    --evaluate-on-save \
    --output-dir output/chatdev_<域>
```

各参数语义见 [main.py#L1275-L1450](file:///home/xhgong/project/EvoMAS/main.py#L1275-L1450)。

### 2.2 `main.py` → `_run_baseline()`

入口：CLI 发现传了 `--baseline` 就不走 Meta-Model 演进，直接进入 `_run_baseline()`，见 [main.py#L225-L350](file:///home/xhgong/project/EvoMAS/main.py#L225-L350)：

```
 _run_baseline()
   ├── 解析 pool_dir （AUTO_POOL_DIR 映射 → mas_pools/swebench）
   ├── 找 target YAML：mas_pools/swebench/chatdev.yaml
   ├── 读 task_ids：scripts/selected_<域>.txt（40/40/34/32 共 146）
   ├── _setup_baseline_logging(output_dir)  # 创建 output_dir + tee → run.log
   └── interpret_mas(
           config=chatdev.yaml,
           dataset=swe_bench_verified,
           task_ids=...,
           output_dir=...,
           evaluate_on_save=True,
           llm_as_judge=None
       )
```

### 2.3 `interpret_mas()` → MasRunner

[interpret_mas](file:///home/xhgong/project/EvoMAS/src/mas/interpreter.py) 做的事：

1. 通过 `loader.py` 把 YAML 解析成 `MASSpec`（agents 列表 / router / merger / evaluator）
2. 实例化各 Agent Runner（对 swebench = MinisweagentRunner）
3. 调 MasRunner 跑数据集

### 2.4 `MasRunner` 关键方法（[mas_runner.py#L332-L1999](file:///home/xhgong/project/EvoMAS/src/utils/mas_runner.py#L332-L1999)）

对外有两个入口：
- **串行**：`run(task_ids=[...])`（本次 ChatDev Baseline 默认走它，每个域内部顺序跑 case）
- **并行**：`run_parallel(workers=4, task_ids=[...])`（多进程跑），但每个域里内部没开并行，并行是 bash 层跨域做的。

单 case 执行链（`run_single_task`）：

```
run(task_id)
  └── run_single_task(task_id)      # L1251
        ├── _is_task_cached         # 已有 .txt 就跳过（use_cache）
        ├── _checkout_base_commit   # 对 SWE-bench：git reset 到 instance 对应 base
        ├── _run_with_timeout       # task_timeout 默认 1800s；超时做 partial metadata 返回
        │     └── interpret_mas.runtime 实际执行（Agent 在 repo 里改文件）
        ├── _save_task_output       # L853：结果写入 <task_id>.txt + metadata 入队
        ├── _evaluate_patch_on_save # L915：如果 evaluate_on_save=True（且是 swe）
        │     └── _evaluate_patch_via_docker  # L976：**当前推荐路径（Docker harness）**
        │           ├── 写 predictions.json（DICT 格式，provider 前缀 openai/）
        │           ├── swebench.run_evaluation(instance_ids=[this], ...)
        │           └── 把 docker_resolved/docker_patch_applied/docker_status 回填 metadata
        └── → MasRunResult（带 result / error / metadata / correct / ground_truth）
```

全部 case 跑完后，`run()` 调 `_save_consolidated_results()` → 写 `results.json`（合并 `_all_metadata` 数组），最后调用 `_print_summary()` 打印汇总。

### 2.5 MinisweagentRunner 的 Docker 模式（[minisweagent.py#L368-L615](file:///home/xhgong/project/EvoMAS/src/agents/runners/minisweagent.py#L368-L615)）

关键新改动：**agent 工作流本身也在 Docker 容器里执行**，不再依赖 host conda 环境是否装了 scikit-learn C 扩展等。

YAML 开关在 [mas_pools/swebench/chatdev.yaml#L49-L50](file:///home/xhgong/project/EvoMAS/mas_pools/swebench/chatdev.yaml#L49-L50)：
```yaml
use_docker: true
agent_config: swebench
```

执行流：
```
MinisweagentRunner.create_agent(instance_id)
  └── build_image_name(...) → swebench/sweb.eval.x86_64.<repo>_<repo>-<issue>:latest
  └── DockerEnvironment(
          image=...,
          cwd="/testbed",           # 关键：repo 根目录
          forward_env=[OPENAI_API_KEY, OPENAI_BASE_URL, LITELLM_*, MSWEA_*],
          container_timeout="2h",
      )
  └── miniswe.TrajectoryAgent(env=env, tools=[bash, edit, ...])

MinisweagentRunner.run(task=problem_statement)
  └── agent.run(task)               # 多轮调用 LLM + 容器里 bash/edit 操作
  └── on submit:
        └── _get_git_diff(repo_path="/testbed")   # 从容器里 git diff 拿最终 patch
  └── return AgentResult(result=diff, metadata={input/output/total_tokens, duration,...})
```

### 2.6 评估层：`run_swebench_docker_eval.py`（**推荐兜底评估**）

单 case 评估用 `_evaluate_patch_via_docker` 是方便的，但如果 provider prefix / format 不匹配就会显示 error_ids。因此**全域评估的黄金路径**仍然是：先让所有域把 `*.txt` + `results.json` 写完，再统一调这个脚本。见 [scripts/run_swebench_docker_eval.py](file:///home/xhgong/project/EvoMAS/scripts/run_swebench_docker_eval.py)：

```
run_domain(domain)
  ├── load_predictions()
  │     └── 读 output/chatdev_<域>/output_selected/swe_bench_verified/<MODEL>/*.txt
  │           → [{instance_id, model_name_or_path, model_patch}, ...] (list of dicts)
  ├── write_predictions() → /tmp/preds_<域>_<ts>.json
  ├── swebench.run_evaluation(
          dataset_name="SWE-bench/SWE-bench_Verified",
          split="test",
          instance_ids=[...],
          predictions_path=...,
          max_workers=4,
          open_file_limit=4096,
          run_id="evomas_docker_<域>",
          timeout=900,
          modal=False,
          report_dir=...,
      )
  └── merge_results_back()
        ├── 读 <REPORT_DIR>/<MODEL>.<run_id>.json → resolved_ids 等集合
        ├── 写回 results.json 的每条 entry：
              docker_resolved / docker_status / docker_patch_applied / docker_infra_failure
              并把 resolved / resolved_reason 更新到本地字段
        └── 打印 per-instance summary
```

⚠️ **predictions 格式的坑**：
- swebench 同时接受 `list` 或 `dict`（keyed by instance_id）两种格式
- 但 `model_name_or_path` 必须和 swebench 在 `<report_dir>/<model>.<run_id>.json` 路径里替换 `"/" → "__"` 的那一段一致
- 历史成功的写法是 `openai/Deepseek-V4-Flash-0731` 或 `chatdev_Deepseek-V4-Flash-0731`（后者是 `run_swebench_docker_eval.py` 的 `DEFAULT_MODEL`，报告路径也统一）

## 5. 近期关键改动（踩坑历史，8/22 快照）

1. **agent 进入容器执行（MinisweagentRunner `use_docker=True`）**：彻底消除 matplotlib / scikit-learn 等 C 扩展在 host conda 里缺失的问题。注意点：镜像名必须按 instance 精确映射，`cwd="/testbed"`（repo 根），并 forward LLM keys 到容器环境。
2. **agent patch 提交格式**：`agent_config: swebench` → 让 agent 最后用 `cat patch.txt` 方式提交；之前写 `echo COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT` 会拿不到 patch 内容，导致 7 个 empty patch。
3. **评估阶段走 swebench docker harness**：新增 `_evaluate_patch_via_docker`（per-task）和脚本 `run_swebench_docker_eval.py`（batch 兜底）。`MasRunner.run` 中新增 `_evaluate_patch_on_save` 调用（放在 `_save_task_output` 之后）。
4. **swebench.run_evaluation 必须传的参数**：`open_file_limit=4096` 和 `modal=False`。少了会 `TypeError`。
5. **predictions 格式坑**：之前 `_evaluate_patch_via_docker` 写的 list 格式 + 不带 provider prefix，导致 sklearn-11578 报 error_ids 但没具体 failure_reasons；已统一改成 **dict 格式 + 自动补 `openai/` prefix**，对齐全域成功的写法。
6. **patch 逻辑 bug vs apply 错误的区分**：`git apply --check < patch.txt` 能过 = apply 没问题，测试 fail 就是**逻辑错误**（典型：丢了 `fit_intercept`）；用 `logs/run_evaluation/<...>/test_output.txt` 里的 `Traceback` 和 pytest FAILED 定位。
